# 存储填充 / Storage Fill

面向 Minecraft 1.20.1 Forge 的模组，为 JEI 配方补料和 FTB Quests 物品任务接入存储网络及精妙背包。

模组 ID：`storage_fill`。版本：`1.0.0`。客户端和服务端应安装相同版本。

## JEI 配方查询与填充

在 JEI 配方填充按钮下方增加材料查询按钮。点击哪个配方的查询按钮，就只查询该配方需要的材料；成功后按钮变绿并显示材料来源，材料不足时变红。

只保留当前被查询配方的一份结果。查询其他配方时覆盖旧结果，关闭 JEI 配方界面时释放。不会因为打开工作台、切换配方或悬停按钮而自动扫描整个仓库，也不通过隐藏打开终端获取库存。

查询成功后，原填充按钮可以从存储中补齐玩家背包缺少的材料。点击时重新核对实际库存、访问权限、范围和能量；缺料时取消填充并提示，不能确认原因时说明来源当前不可用。查询结果不是实时库存，存储变化后可再次点击查询按钮。

普通点击填充一次配方；Shift 在规则明确的处理器上按 JEI 原生行为尽量填满，遵守材料数量、NBT 和槽位上限。未知批量规则的第三方处理器只补一次配方所需材料，再交给原处理器执行。

支持普通工作台、玩家 2×2 合成和兼容的机器处理器。Apotheosis-Artifice 机械渡鸦附魔台有已确认的 Shift 补料适配。材料取用优先玩家背包及输入槽，其次存储网络，最后精妙背包。

## FTB Quests 联动

FTB Quests 为可选依赖，主要支持普通物品任务。

### 非消耗物品任务

物品进入存储后，安排检测相关已解锁任务，按照当前可访问库存数量判断，不取走物品。例如分四次存入各 16 个铁锭且保留库存，可以满足 64 个铁锭的任务；反复取出再放回同一批 16 个不会累计成 64。

沿用任务原生 NBT、前置、顺序和队伍锁定规则。前置完成、新任务激活、登录、换队及发现来源变化时补检。手动领完可重复任务的奖励后，遵守原生冷却，再检测下一轮一次；自动领取保留同一检测波内的重复保护。

多个存储来源及玩家背包采用保守去重，取较大库存判断，不直接相加；已记录进度遵循 FTB 原生规则，取走物品不会回退进度。

检测以事件触发为主，空闲时不持续读取库存。绕过已适配插入接口的外部库存变化，或没有触发相关事件的访问条件恢复，不保证立即检测。任务冷却中退出后重新登录，也可能需要后续事件再次唤醒。

### 消耗物品任务

点击 FTB 原生提交按钮时，先使用玩家主背包，不足再从可访问存储实际提取并提交。允许部分提交，提示已提交数量及剩余缺口；按 FTB 实际接受量扣除物品，保留完整物品数据。

不自动提交消耗型任务。仅任务屏幕任务、物品过滤器和自定义 ItemTask 子类保留其原有流程。

### 物品奖励去向

任务书右下角原按钮组顶部增加去向按钮，展开后单选：

| 去向 | 图标 |
| --- | --- |
| 玩家背包 | 工作台 |
| 精妙背包 | 普通背包 |
| Refined Storage | 创造控制器 |
| Applied Energistics 2 | 控制器 |
| 超越维度网络 | 维度网络发生器 |

只有安装对应模组时才显示该选项。选择会保存；目标不可用或空间不足时，剩余奖励回玩家背包，背包也满时按原生方式掉落。

精妙背包的无 NBT 奖励正常堆叠；带 NBT 的奖励只进入空槽，不与已有物品合并。规则也涵盖显式空 tag 和序列化能力数据。保留原生过滤、容量和写入后数量确认，不通过虚空升级吞掉奖励，也不把无限模板槽当普通空槽。

## 存储兼容

四个适配独立启用，可单独或组合安装。

| 来源 | 访问条件 |
| --- | --- |
| 超越维度 | 玩家拥有当前可访问网络成员身份 |
| Refined Storage | 携带已绑定的原生无线终端，网络有效、在无线范围内、有相应权限且能量足够 |
| Applied Energistics 2 | 携带已绑定的无线终端或无线合成终端，网络供电、范围、权限及能量满足要求 |
| 精妙背包 | 使用官方玩家背包提供器可访问的主储物格，不主动搜索世界内或递归展开嵌套背包 |

实际取料和插入遵守对应存储的访问规则。配方填充只使用已有物品，不请求存储网络自动合成。

## 构建

设置 `JAVA_HOME` 指向 Java 17。工程使用本地 `libs/` 依赖；第三方 JAR 不随仓库分发，需要自行取得对应文件并放入该目录：

```text
jei-1.20.1-forge-15.59.0.212.jar
refinedstorage-1.12.4.jar
beyonddimensions-0.7.20.jar
appliedenergistics2-forge-15.4.10.jar
guideme-20.1.15.jar
sophisticatedbackpacks-1.20.1-3.26.3.2157.jar
sophisticatedcore-1.20.1-1.5.1.2335.jar
ftb-quests-forge-2001.4.22.jar
ftb-library-forge-2001.2.9.jar
ftb-teams-forge-2001.3.0.jar
architectury-9.2.14-forge.jar
```

Windows：

```powershell
.\gradlew.bat test build
```

Linux / macOS：

```sh
./gradlew test build
```

产物位于 `build/libs/storage_fill-1.20.1-1.0.0.jar`。不会自动部署到游戏目录。

游戏内集成测试还需要相应运行时模组及满足其自身要求的前置版本。上表区分编译依赖与已验证运行依赖；启用 FTB 的测试时，应按运行版本调整 `runtimeOnly` 依赖。请使用专用测试目录和存档。

## 验证范围

最新奖励规则变更通过 61 项单元测试、47 项相关 Forge GameTest，以及 2 项原生背包性能 GameTest。覆盖部分提交、NBT/能力数据、过滤与特殊分区、写后异常、Choice 防重和可重复任务领取。

大仓库、复杂替代材料配方和第三方外部存储仍可能增加同步查询耗时。自动检测的 2 毫秒是软调度预算，不能中断已经执行中的原生存储接口。本机夹具结果不等于完整整合包的长期多人表现。

可编辑查询图案保留在 [recipe_query_16.bbmodel](src/main/art/gui/recipe_query_16.bbmodel)。
