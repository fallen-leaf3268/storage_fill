# 存储填充 / Storage Fill

面向 Minecraft 1.20.1 Forge 的模组，为 JEI 配方补料和 FTB Quests 物品任务接入存储网络及精妙背包。

模组 ID：`storage_fill`。版本：`1.0.0`。客户端和服务端应安装相同版本。

## JEI 配方查询与填充

在 JEI 配方填充按钮下方增加材料查询按钮。点击哪个配方的查询按钮，就只查询该配方需要的材料；成功后按钮变绿并显示材料来源，材料不足时变红。

查询按钮跟随 JEI 原生填充按钮显示；当前工作方块不匹配、原生填充按钮隐藏时，查询按钮同时隐藏。工作方块匹配但背包缺少材料时，仍可点击查询存储。

只保留当前被查询配方的一份结果。查询其他配方时覆盖旧结果，关闭 JEI 配方界面时释放。不会因为打开工作台、切换配方或悬停按钮而自动扫描整个仓库，也不通过隐藏打开终端获取库存。

查询成功后，原填充按钮可以从存储中补齐玩家背包缺少的材料。点击时重新核对实际库存、访问权限、范围和能量；缺料时取消填充并提示，不能确认原因时说明来源当前不可用。查询结果不是实时库存，存储变化后可再次点击查询按钮。

普通点击填充一次配方；Shift 在规则明确的处理器上按 JEI 原生行为尽量填满，遵守材料数量、NBT 和槽位上限。未知批量规则的第三方处理器只补一次配方所需材料，再交给原处理器执行。

支持普通工作台、玩家 2×2 合成和兼容的机器处理器。原生玩家 2×2 处理器接入标准槽位填充流程，普通点击补一次、Shift 尽量填满，避免先补入背包后恢复填充被内部等待状态阻挡。Apotheosis-Artifice 机械渡鸦附魔台有已确认的 Shift 补料适配。材料取用优先玩家背包及输入槽，外部来源默认依次为超越维度、RS、AE2、精妙背包，可通过个人配置调整。

## 配方填充优先级配置

首次启动后生成游戏目录下的 `config/storage_fill-client.toml`。每位玩家修改自己的文件，联机时服务端按当前玩家查询时提交的顺序取料。玩家背包和配方输入槽始终优先。默认配置：

```toml
[recipeFill]
sourceOrder = ["beyonddimensions", "refinedstorage", "ae2", "sophisticatedbackpacks"]
```

四个名称分别对应超越维度、精致存储 RS、应用能源 AE2、精妙背包。将名称移到列表前面即可提高该来源的取料优先级。只列部分来源时，其余来源按默认顺序追加；重复项忽略，无效名称由 Forge 校正，未安装或不可访问的来源自动跳过。该列表调整取料顺序，不用于禁用来源。

保存配置后重新点击配方查询按钮生效；已查询的配方保留查询时的顺序，查询提示和实际取料共用该顺序。仍保持单配方结果、满足需求即停止查询，不为比较所有替代物品或 NBT 变体扫描整个仓库。此配置不改变 FTB 任务的库存检测和奖励去向。

联机需要客户端与服务端同时更新；本次配置同步使用网络协议 11。

## FTB Quests 联动

FTB Quests 为可选依赖，主要支持普通物品任务。

### 非消耗物品任务

物品进入存储后，安排检测相关已解锁任务，按照当前可访问库存数量判断，不取走物品。例如分四次存入各 16 个铁锭且保留库存，可以满足 64 个铁锭的任务；反复取出再放回同一批 16 个不会累计成 64。

沿用任务原生 NBT、前置、顺序和队伍锁定规则。前置完成、新任务激活、登录、换队及发现来源变化时补检。手动领完可重复任务的奖励后，遵守原生冷却，再检测下一轮一次；自动领取保留同一检测波内的重复保护。

多个存储来源及玩家背包采用保守去重，取较大库存判断，不直接相加；已记录进度遵循 FTB 原生规则，取走物品不会回退进度。

检测以事件触发为主，空闲时不持续读取库存。绕过已适配插入接口的外部库存变化，或没有触发相关事件的访问条件恢复，不保证立即检测。任务冷却中退出后重新登录，也可能需要后续事件再次唤醒。

### 消耗物品任务

点击 FTB 原生提交按钮时，先使用玩家主背包，不足再从可访问存储实际提取并提交。允许部分提交，提示已提交数量及剩余缺口；按 FTB 实际接受量扣除物品，保留完整物品数据。

不自动提交消耗型任务。仅任务屏幕任务、物品过滤器和自定义 ItemTask 子类保留其原有流程。

### 物品奖励去向

任务书右下角原按钮组顶部增加去向按钮，展开后单选：

| 去向 | 图标 |
| --- | --- |
| 玩家背包 | 工作台 |
| 精妙背包 | 普通背包 |
| Refined Storage | 创造控制器 |
| Applied Energistics 2 | 控制器 |
| 超越维度网络 | 维度网络发生器 |

只有安装对应模组时才显示该选项。选择会保存；目标不可用或空间不足时，剩余奖励回玩家背包，背包也满时按原生方式掉落。

精妙背包的无 NBT 奖励正常堆叠；带 NBT 的奖励只进入空槽，不与已有物品合并。规则也涵盖显式空 tag 和序列化能力数据。保留原生过滤、容量和写入后数量确认，不通过虚空升级吞掉奖励，也不把无限模板槽当普通空槽。

## 存储兼容

四个适配独立启用，可单独或组合安装。

| 来源 | 访问条件 |
| --- | --- |
| 超越维度 | 玩家拥有当前可访问网络成员身份 |
| Refined Storage | 背包或 Curios 实际佩戴栏中的已绑定原生无线物品终端、Refined Storage Addons 无线合成终端（不含装饰栏），网络有效、在无线范围内、有相应权限且能量足够 |
| Applied Energistics 2 | 携带已绑定的无线终端或无线合成终端，网络供电、范围、权限及能量满足要求 |
| 精妙背包 | 使用官方玩家背包提供器可访问的主储物格，不主动搜索世界内或递归展开嵌套背包 |

实际取料和插入遵守对应存储的访问规则。配方填充只使用已有物品，不请求存储网络自动合成。

Legendary Inventory 1.1.0 的标准填充请求可通过独立槽位映射识别玩家自己的滚动背包，保留真实物理槽位去重、权限和物品守恒校验。仅按当前窗口处理，不扫描隐藏的整个扩展背包。该模组不是必装依赖。

此适配不代表完整的 Legendary Inventory 联动：它自带的 JEI 配方处理器使用内部库存预检缓存，在本轮默认组合下查询仍可能显示未完成。当前不替换其处理器、不修改其缓存，也不改变本模组的查询、分配和提取流程。

## 构建

设置 `JAVA_HOME` 指向 Java 17。工程使用本地 `libs/` 依赖；第三方 JAR 不随仓库分发，需要自行取得对应文件并放入该目录：

```text
jei-1.20.1-forge-15.59.0.212.jar
refinedstorage-1.12.4.jar
refinedstorageaddons-0.10.0.jar
legendaryinventory-forge-1.20.1-1.1.0.jar
curios-forge-5.14.1+1.20.1.jar
beyonddimensions-0.7.20.jar
appliedenergistics2-forge-15.4.10.jar
guideme-20.1.15.jar
sophisticatedbackpacks-1.20.1-3.26.3.2157.jar
sophisticatedcore-1.20.1-1.5.1.2335.jar
ftb-quests-forge-2001.4.22.jar
ftb-library-forge-2001.2.9.jar
ftb-teams-forge-2001.3.0.jar
architectury-9.2.14-forge.jar
```

Windows：

```powershell
.\gradlew.bat test build
```

Linux / macOS：

```sh
./gradlew test build
```

产物位于 `build/libs/storage_fill-1.20.1-1.0.0.jar`。不会自动部署到游戏目录。

游戏内集成测试还需要相应运行时模组及满足其自身要求的前置版本。上表区分编译依赖与已验证运行依赖；启用 FTB 的测试时，应按运行版本调整 `runtimeOnly` 依赖。请使用专用测试目录和存档。

## 验证范围

本轮旧版 JEI 兼容在 Forge 47.4.18 下检查了 15.20.0.129、15.35.0.175、15.40.0.176、15.48.0.185、15.49.0.200、15.56.0.205、15.57.0.207、15.59.0.212、15.71.0.224 和 15.74.0.227，十组单元及 Mixin 目标检查无失败；现代版本跳过仅针对旧接口的异常恢复用例。生产字节码的 JEI 类与成员检查无缺失，旧按钮从 Minecraft 继承的成员另由真实客户端覆盖。

真实 RS 1.12.4 客户端完成 14 组查询、普通填充、Shift、服务端回执、库存守恒和关闭释放检查：15.20、15.40、15.57、15.59、15.71、15.74 各覆盖工作台 3×3 剪刀与玩家 2×2 木板；15.35、15.56 覆盖工作台剪刀。各版本还检查工作方块不匹配时两个按钮隐藏且不发查询。本轮没有拦截传输包或注入伪造库存，不据此声称所有中间构建均逐一启动验证。

15.20 的原生配方槽位视图每次读取都会创建新对象，已先复现真实点击后查询身份不一致，再稳定每个旧版布局的实时视图引用。库存结果仍只有当前配方一份，替换或关闭时释放；没有放宽配方匹配或更改存储取物规则。

JEI 15.20 搭配 RS 和 FTB 的服务端完成 259 项登记 GameTest，无必需用例失败；缺少相应依赖的集成用例按日志跳过。

JEI 15.20.0.129 和 15.59.0.212 另分别通过真实 BD 网络与第三方处理器测试夹具的完整客户端集成，覆盖补料、取消、过期库存提示、单配方结果复用及关闭释放、标准服务端回执和 Shift 最大填充。测试经相应版本的原生 JEI 入口执行，没有跳过旧版后段断言；不据此声称已实测所有第三方机器。

Legendary Inventory 槽位修复在 Forge 47.4.18 / JEI 15.59.0.212 下先复现服务端标准工作台剪刀请求的 `storage_fill.failed.invalid`，再通过 7 项实际模组槽位回归，覆盖普通/Shift、滚动、筛选、隐藏空槽、重复物理映射、归属限制和数量守恒。外部来源使用内存夹具，未据此宣称真实 RS 客户端与默认 Legendary Inventory 自带 JEI 处理器完整兼容。未安装 Legendary Inventory 的 Forge 47.4.26 / JEI 15.71.0.224 组合另完成回归，保留可选依赖隔离。

Refined Storage Addons 0.10.0 在 Forge 47.4.18 / JEI 15.59.0.212 / RS 1.12.4 下通过真实客户端查询、普通填充和 Shift 最大填充测试，确认数量守恒。原生背包无线终端在同一组合下也通过该流程。此次附属支持修复的是终端类型漏识别，不需要更换 JEI。

新增 5 项 RSA 原生 GameTest 已实际执行，覆盖背包与 Curios、真实终端扣费、模拟不扣费、混合终端去重与替换、权限、无线范围、缺电、创造终端及无关终端排除。测试采用不同的原生与附属开启费用，确认读取对应配置；保持现有定向查询，没有新增后台轮询、全仓扫描或库存缓存。

个人优先级和 RS Curios 修复在 Forge 47.4.26 搭配 JEI 15.71.0.224、15.59.0.212 的两种运行依赖下分别通过 73 项单元测试。RS 1.12.4 搭配 Curios 5.14.1+1.20.1 的四项原生回归先在旧代码上得到漏扫终端的预期失败，再在修复后通过；覆盖佩戴发现、移动/替换/移除、实际 RF 扣费、模拟不扣费、无线范围、权限和装饰栏排除。另验证未安装 Curios 时的 RS 兼容。

查询按钮隐藏修复在 JEI 15.59.0.212 / Forge 47.4.18 和 JEI 15.71.0.224 / Forge 47.4.26 下分别通过 64 项单元测试及 152 项客户端断言，覆盖错方块隐藏、隐藏点击不触发查询、匹配缺料仍可查询、红绿状态及提示、关闭释放、书签位置恢复和极矮配方布局。本次界面回归拦截查询包并注入服务端应答，未重复真实存储网络集成测试。
